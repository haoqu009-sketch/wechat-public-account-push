# 私有匹配资料

`RECRUITMENT_PROFILE_JSON`由`profile.mjs`校验并合并到基础画像。仅允许以下字段：

- `degreeType`：`学硕`或`专硕`。
- `birthYear`：1950–2010的整数；仅年份不能解决年龄边界附近的精确判定。
- `specialty`：用户提供的研究生专业全称，覆盖基础配置中的通用专业名称。
- `residencySpecialty`：用户提供的规培合格证专业，独立于研究生专业。

专业名称最多80字符，只允许专业名称所需的中英文、数字及有限标点。拒绝未知键、HTML和控制字符；不接受或根据名称自动补齐专业代码。用户明确更正学位类型时只覆盖该字段，不据专业名称推断学硕/专硕。

真实个人资料只保存于服务器两个root:root 0600环境文件，不写入config.json、Git、静态网页目录或公共报告。公共证据只显示官方要求及核对结论，不导出个人画像。

规培要求仅在原文明确列出单个专业名称、与用户提供名称完全一致且已完成规培时确认名称一致。近义名称、专业对应关系、复合条件继续保留疑点；不会据此确认执业注册、工作年限或所有报名资格。

修改受保护资料须使用既有全局flock：先备份权威state、pending、完成标记和两个环境文件，验证依赖锁一致，原子写入环境并切换支持这些字段的版本。失败恢复原环境与release，不重置状态。只调用refresh进行复核，不调用daily或发送预览。

发布后应检查：两个环境的修改字段符合用户最新确认，其他画像及环境字段不变，收件人/已发送记录、pending、完成标记和timer不变；新报告晚于资料更新时间，公网latest与不可变快照一致。
